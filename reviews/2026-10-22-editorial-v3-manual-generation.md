# Future editorial policy and manual generation — 2026-10-22

New manual requests have account-qualified UUID idempotency keys and no application daily cap. They no longer reopen the scheduled daily job. One/two-draft limits apply per request; provider limits, event claims and the global worker lease still apply. A persistent request mapping preserves retry identity even when a concurrent request joins an existing worker. The browser retains an uncertain request across a reload. Scheduled daily/weekly keys are unchanged.

`site-publishing-v3.sql` adds service-only coordination and pins only new jobs to editorial version 3. Existing jobs retain version 2. It was applied to production after PGlite migration/idempotency/concurrency/permission checks. Production article count was 100 before and after, article-content fingerprint `4ec4a1f62a58bbcd38484bb177acd258`, and the three existing checkpoint fingerprint was `241153c3c0d83657b72975b49019cff6`. All fingerprints matched. Anonymous enqueue permission is false. The existing automatic setting was true and remained true; manual jobs always require private review.

Version 3 builds an explicit reader question, development, context and unknowns. Activity titles/findings and comparisons are generated from bounded recorded observations. Inclusive display dates use the exclusive end minus one millisecond. Model prose cannot generate statistical claims; code retains title/metric/period/value associations. Saved evidence is recalculated before acceptance. Raw Markdown, repeated sections and unsupported broad/causal headlines are rejected. Gemini 2.5 Flash, bounded transport recovery and one editorial revision remain unchanged. These checks do not replace human editorial judgement or promise Google rankings.

Quiet-day reports are baseline reports or require a changed ranking across comparable, nonoverlapping observations. The same period, shifted overlapping windows, incompatible coverage and numerical drift alone are skipped. Weekly jobs remain independent. An unavailable provider is not reported as an empty news day.

Authenticated preview and public/initial HTML use the same typed version-3 body. Legacy articles retain their old rendering. New articles show one headline/summary, one results chart/table and one methodology section. Exact observations are retained with the article, accessed through a published-only read endpoint and omitted from normal article JSON/bootstrap payloads. Public article, evidence and sitemap reads do not generate content. Admin configuration rows now say Configured; the database-backed admin-table read says Read verified rather than implying active monitoring.

Verification: TypeScript; full frontend suite; seven new model/policy/database/evidence regressions plus existing publishing/review/Calendar/gateway and initial-HTML regressions; 19 web/account/route contracts; production frontend build and asset budget; final server build and 13 local production routes. Initial sandbox Vite realpath and loopback restrictions were rerun successfully with normal filesystem/local HTTP access. No desktop source, version or installer changed.

Production deployment and a new private-run acceptance are recorded after rollout. Existing articles, URLs, saved drafts and automatic settings are outside this change. No acceptance draft is to be published.
