# StreamNyaa Desktop 0.1.9 player repair

## Changes

- Keep the settings panel in the same position and size across submenus, including paused playback. Fit long menus into a scrollable viewport with room for Back.
- Retain the current hover target after drawing. Pointer movement within a settings row no longer redraws the complete overlay repeatedly.
- Paint pressed feedback on mouse-down, including menu rows and submenu options; commit actions once on a matching release. Keep interruption, drag cancellation and resize protections.
- Include the previous fixes for buffering redraws dropping clicks, double-click events toggling settings twice, stale preference sync and unanswered Next requests.
- CC opens subtitle choices/import rather than silently doing nothing when no subtitle track is selected. The keyboard toggle explains absent tracks.
- Downloads displays immediate opening feedback. Its actual manager still requires the StreamNyaa native shell; a standalone diagnostic player cannot validate that bridge.
- Display native automatic aspect-ratio values as Default instead of a negative number.
- Bump Tauri, Cargo and Settings fallback version to 0.1.9. Preserve application identity and data compatibility.

## Evidence

The user's input log showed a subtitle-picker dispatch and an Appearance submenu dispatch, followed by clicks outside the newly repositioned panel that dismissed it. This supports the stable-panel repair, but is not proof that every reported unresponsive button shared that cause.

The prior redraw implementation reset the hovered row on every draw. A regression now asserts that 20 movements within the same row do not cause additional draws. Other regressions check immediate pressed feedback while paused, identical panel bounds across submenus and native automatic aspect normalization.

Final player-state suite: 510 assertions pass. TypeScript, 192 frontend tests, 15 web tests, desktop contracts, native controls, stall and 100-cycle soak pass. Rust: 56 pass, 1 existing ignored test.

## Open acceptance gates

Final-source paused native player launched on local test media, but Windows input returned `GetCursorPos failed: Access is denied. (0x80070005)`. Full native action/latency acceptance, integrated download/subtitle chooser/next-episode dispatch, real footage and the 100/150/200 percent scaling matrix remain unverified. Tests and code fixes do not constitute a claim that every user-reported failure is resolved.

No signing material or isolated installation environment is available. Preserve the existing 0.1.8 installer. Build 0.1.9 separately and identify it as unaccepted pending native validation. Record installer checksum, size and extracted resource comparisons in its manifest.
