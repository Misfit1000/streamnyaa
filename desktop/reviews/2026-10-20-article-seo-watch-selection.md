# Article HTML, editorial checks and Watch selection — 0.1.11

The desktop Use control identifies the selected release, carries it into the main Play/download actions, and uses a stable hash key across magnet enrichment and hash casing. Verified failed releases can be deliberately retried from Broad results without entering automatic recommendations. Identity, episode, audio, quality and eligibility changes still invalidate selection. Review & play and its manual playback override were removed at the user's request; unverified releases retain details and download tools.

Individual website articles render the existing React presentation and website shell on the server for every reader. Initial HTML contains the article, sources, canonical address, title, description, social metadata and structured data. Public article bootstrap avoids a second article fetch on client startup. Fixed section aliases redirect to the saved article URL. Confirmed missing articles return 404; storage outages return a non-cacheable 503. Rendering and public reads cannot call Gemini or publish. The HTML and generated renderer are packaged with the existing Blog API function rather than adding a function.

The new editorial gate adds repeated-padding, exaggerated-headline and invented-firsthand-reporting checks, applies current validation to resumed drafts, and labels AI assistance. The prompt asks for source-backed practical consequences, context and explicit unknowns rather than a target word count. Automated checks do not establish factual expertise or human editorial acceptance. The archived Blue Box example still has unsupported interpretations of metrics; old articles have not been retroactively certified or rewritten.
